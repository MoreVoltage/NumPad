## 1. Product thesis

NumPad's thesis is that the iPhone's numeric keyboard is currently invisible infrastructure with no
ambition — sixty-year-old ten-key convention, hidden behind whatever app happens to need a number,
while text keyboards get themes, AI, and platform depth. NumPad claims **the numeric layer of iOS**:
not "a keyboard app" but the one trusted surface every number on the device passes through — typed,
converted, tallied, tipped, remembered, and now spoken to Siri or surfaced on a Lock Screen. Every
shipped and proposed feature sits on the same small set of pure, offline compute primitives
(`Calculator`, `TaxTipMath`, `UnitConverter`) and the same App Group data model (`ResultTape`,
`ClipboardHistoryManager`, `SnippetsManager`, `CustomKeyboardConfig`), which is exactly what lets a
50MB keyboard extension credibly reach into Siri, widgets, Live Activities, a Mac companion, and
vertical professional tools without breaking its no-subscription, no-network-without-consent trust
posture. The bet: "the numpad" becomes as ownable a category as "the weather app" — through
installed base, reviews, and a growing list of professions (bookkeepers, field engineers, kiosk
operators) who would notice immediately if it disappeared.

## 6. The acquisition narrative — 5 bullets for a $20M valuation

Each bullet is stated honestly against today's baseline, with the metric target that would need to
be true before an acquirer should treat it as real rather than aspirational.

1. **Installed base + review-volume category ownership ("the numpad," like "the weather app").**
   *Target:* 250K+ lifetime installs, 4.7★+ average across 5,000+ ratings, top-10 App Store ranking
   for "numpad"/"number keyboard" search terms. *Honest baseline:* 180 first-time downloads and 0.7%
   page conversion over the last 90 days — this bullet does not exist yet. It only becomes real if
   the Growth-lens Tier 1/2 items (referral loop, ASA, bundles, Lucky Digits/Receipt-driven organic
   sharing) compound over multiple quarters, not a single release.

2. **B2B contract base (NumPad Fleet / kiosk deployment).** *Target:* 15+ signed organizational
   contracts, 3,000+ managed devices under volume licensing, $200K+ trailing-12-month B2B ARR.
   *Honest baseline:* the B2B validation brief is explicit that there are **zero committed
   customers** today and discovery calls haven't happened. The underlying tech (Product A) already
   works with no new engineering — this bullet is 100% sales-execution risk, not technology risk,
   which is exactly why it's cheap to start now (Tier 1 #5) and expensive to fake later.

3. **OS-level automation lock-in (Numeric Workspace API).** *Target:* 20%+ of monthly active users
   with at least one Siri Shortcut, App Intent, or widget actively wired to NumPad data (measurable
   via intent/widget engagement events once shipped). *Honest baseline:* the App Intents surface
   (Ask NumPad) just shipped in `6725209c` — real, verified, done — but the *lock-in* half (a widget
   or Live Activity that reads/writes `ResultTape` so ripping NumPad out breaks a user's other
   automations) is not built yet. This bullet is de-risked, not delivered.

4. **A working non-subscription monetization engine an acquirer could scale with distribution.**
   *Target:* store-page conversion above 2% (from a 0.7% baseline), $15K+/quarter IAP revenue
   run-rate, ≥1.5 packs owned per paying user (bundle + trial-funnel attach). *Honest baseline:*
   $337 in the trailing 90 days — a rounding error today. This is the least defensible bullet in
   isolation and the most important one in aggregate: without it, bullets 1–3 describe a feature-rich
   product with no proof anyone will pay for it.

5. **A transferable IP/diligence asset beyond "we shipped first."** *Target:* 2 narrow patent
   applications filed (reserved-gesture-precedence disambiguation, parallel-array drag-reorder sync)
   with a freedom-to-operate opinion in hand — filed, not necessarily granted, given the 18–36 month
   timeline. *Honest baseline:* prior art exists on the general "customizable keypad" concept
   (three granted USPTO patents surfaced in research); this bullet strengthens a due-diligence
   packet and should never be the load-bearing reason for the valuation — it's optionality, not
   revenue.

**The honest read across all five:** bullet 4 (revenue proof) is the gating bullet — without it,
1/2/3/5 describe a well-built product an acquirer could just as easily build in-house. Sequencing
therefore matters: Tier 1's growth item (Try Before You Buy) and Tier 2's referral/bundle items
exist specifically to make bullet 4 credible before the others get expensive to pursue.

## 7. DO-NOT-BUILD list

1. **Mascot / idle-animation personality.** Novelty decays in days; the council's own Delight lens
   explicitly rejected this in favor of reactive copy (Sass Mode), which never repeats the same way
   because it's driven by the user's own numbers.
2. **A hosted link-sharing backend for Keyboard Cards.** Needs server infrastructure the app doesn't
   have and, per its own no-network-without-Full-Access posture, shouldn't need — AirDrop/file export
   delivers the same social loop with zero new infra.
3. **visionOS presence.** No spatial-computing rationale for a numeric keypad, and third-party custom
   keyboard extensions aren't even supported on the platform today.
4. **A standalone Handoff/`NSUserActivity` continuity feature.** `CloudSync`'s iCloud KVS already
   gives Pro users cross-device continuity within seconds — the incremental value is real but too
   small to be its own workstream; fold into Spotlight work later if ever.
5. **A bespoke StandBy feature.** StandBy's third-party surface *is* the `accessoryRectangular`/
   `accessoryCircular` widget family — Live Tape (Tier 1 #2) buys this for free; building it
   "separately" duplicates work.
6. **"NumPad replaces the barcode scanner."** A connected Bluetooth HID scanner suppresses the
   software keyboard entirely at the OS level — this is a platform dead end, not an engineering gap
   to close. Cycle-Count Tally (manual-entry companion) is the honest adjacent alternative.
7. **Crypto/live-market-data features.** Rejected for needing a live data feed the app's fully
   offline compute posture doesn't support — Position & Risk Calculator only survives council review
   because it needs no live price at all.
8. **Medical/dosage-flavored framing on the Ratio & Proportion Solver.** Any health-claim language in
   copy or screenshots invites regulatory/App-Review risk the generic "ratio and proportion" framing
   deliberately avoids — never let marketing drift there.
9. **Treating themes, Tax/Tip math, Clipboard/Snippets CRUD, or the à-la-carte pricing structure as
   "the moat."** All are commodity or cloneable-in-a-weekend (themes are cosmetic; Tax/Tip is
   ubiquitous; iOS itself is trending toward OS-level clipboard history; the pricing structure is
   visible on the App Store listing to any competitor). Don't spend differentiation budget expecting
   IP value here — spend it on the automation surface and vertical tooling instead.
10. **A generic AI wrapper marketed as the innovation itself.** Calling a public on-device or cloud
    LLM API is not defensible technology by itself — if Ask the Number ships, the pitch has to be the
    integration into an already-trusted numeric workflow, not "we added AI."
11. **Any user-facing "Ask the Number" UI before the extension-process FoundationModels spike
    resolves.** Building the feature before confirming `SystemLanguageModel` is even callable from
    the Keyboard extension target risks a full rebuild if the answer is no.

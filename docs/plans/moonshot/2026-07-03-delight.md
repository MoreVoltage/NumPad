# NumPad Moonshots — Delight & Shareability

Date: 2026-07-03. Branch: `feat/2.0-ux-overhaul`. Research-only — no source changes, not committed.
Lens: what makes someone demo NumPad to a friend within 60 seconds of using it. Grounded against
`docs/plans/2026-07-03-pack-lineup-proposal.md`, `docs/plans/2026-07-03-b2b-validation-brief.md`,
and `CLAUDE.md`'s inventory of what already exists: 6 à-la-carte packs + Pro, 17 themes, Custom
Keyboard editor (with drag reorder + key library palette, shipped `618de734`), iPad heights incl.
Kiosk, iCloud sync, Result Tape (GA), inline calculator overlays, clipboard history, snippets,
TAX/TIP overlay, Units/Cooking conversion overlay.

**Current state check (via code, not assumption):** `Button.swift` fires exactly one haptic
(`UIImpactFeedbackGenerator(.light)`, shared/prepared instance) on every key, every pack, every
theme — no variation. `KeyboardViewController.playClick()` calls `UIDevice.current.playInputClick()`
— the stock system click, not a custom sound; `UserPrefs.soundEnabled` and Full-Access-gating
already exist as the plumbing pattern to extend. Both are strong signals that the interaction layer
is currently undifferentiated — a single flat haptic/sound identity across a product with 6
domain-specific packs — which is exactly the gap several ideas below close.

Prior art consulted: Soulver (task-specific accessory keyboard rows, long-press for extra options,
"napkin that thinks with you"), CARROT Weather (personality as a design differentiator, state
communicated through the UI itself, shareable presets), Flighty (Apple Design Award 2023 —
function-first animation, and the Passport feature: an auto-generated, beautifully rendered
shareable artifact that became one of its biggest organic growth drivers).

## 1. Lucky Digits — numeral easter eggs

**Pitch:** NumPad already sees every digit the user types, locally, before it's inserted. Give the
keyboard a sense of humor about numbers themselves: when the run of digits just typed matches a
curated "fun number" — a repdigit (`777`, `9999`), a palindrome (`12321`), a suspiciously round
milestone (`1,000,000`), or a recognizable constant (`314159`, `271828`) — the keyboard responds
with a quarter-second accent-color pulse around the keys and a distinct `.success` notification
haptic instead of the usual tap. It's not a calculator feature, it's the keyboard noticing something
about what you're typing, which is a category of surprise a numeric keypad has never had before.

**Wow moment:** you idly type `100000` into a price field and the whole keyboard flashes and gives a
little haptic "ding," like it's in on the joke with you.

**Effort:** S. Pure client-local state (a digit-run buffer reset on any non-digit tap, already
tracked the same way `routeIntoCalculatorOverlay` tracks input) + a curated match list + a
`CAGradientLayer`/border-color flash using the *existing* theme accent color (no new assets) + one
`UINotificationFeedbackGenerator(.success)` call gated behind the same `hapticsActive` check
`Button.swift` already has.

**Risk:** Low. Two guardrails keep it from feeling random or invasive: (1) suppress entirely when
`textDocumentProxy.textContentType` is `.creditCardNumber`, `.oneTimeCode`, or `.password` — the
proxy already exposes this, no new capability needed, and it avoids a "why did my card number field
flash" moment; (2) a short per-value cooldown so retyping the same trigger doesn't refire and start
to feel gimmicky. Keep the match list small and tasteful (numeric milestones and constants, not
meme numbers) so it reads as "clever" rather than "trying too hard."

**Wow-per-effort: 9/10**

**First shippable slice:** ship across all packs immediately with ~15 curated triggers (repdigits
100–999999, palindromes ≥5 digits, round numbers 100/1K/10K/100K/1M, π/e/φ digit strings), no
Settings toggle yet — validate reaction/complaint volume before deciding if it needs to be
opt-outable in `UserPrefs`.

## 2. Pack Foley — sound identity per pack

**Pitch:** Right now every pack, every theme, sounds identical — the stock iOS input click. Give
each domain pack its own tiny, unmistakable sound: Finance gets a soft cash-register "cha-ching,"
Programmer gets a mechanical-keyboard click, Cooking gets a light utensil-tap, Units gets a subtle
digital-tick. This is the single most demoable feature in this list — "typing sounds" content is a
proven, recurring viral category on its own (mechanical-keyboard and ASMR-typing apps have gone
viral repeatedly), and NumPad already has the exact plumbing to gate it correctly: Full Access +
`UserPrefs.soundEnabled` already exist as a precedent for "audio requires explicit opt-in."

**Wow moment:** you switch to the Finance pack and every keystroke suddenly sounds like a vintage
cash register — you immediately flip through the other packs just to hear what they sound like.

**Effort:** M. Needs: a handful of very short (<50KB each) `.caf` clips per pack, a preloaded pool of
`AudioServicesSystemSoundID`s (not `AVAudioPlayer`, to keep latency low and avoid audio-session
overhead in a 50MB extension) keyed off the active `KeyboardType`, and swapping `playClick()`'s
single `playInputClick()` call for a pack-aware dispatch. All gated behind the existing
`soundEnabled && hasFullAccess` check — no new permission surface.

**Risk:** Medium. Two real risks, both manageable: (1) App Review sensitivity around custom audio in
keyboard extensions — mitigated by precedent (shipped keyboard-sound apps exist in the App Store
today) and by keeping it strictly opt-in/mutable, same as sound already is; (2) becoming annoying in
quiet public settings — default it off, or scope the pilot to Finance only so a bad take is cheap to
walk back.

**Wow-per-effort: 8/10**

**First shippable slice:** one pack only — Finance's cash-register tick — as a pilot behind
`soundEnabled`. Validate latency (must feel instant, not "played after the fact"), memory footprint,
and App Review response before building out the other 5 packs' sound identities.

## 3. The Receipt — a shareable artifact from Result Tape

**Pitch:** Flighty's Passport and CARROT's shareable presets both prove the same thing: a
beautifully rendered, auto-generated artifact people can text a friend is worth more for organic
growth than any in-app feature alone, because it leaves the app. NumPad's Result Tape already holds
exactly the data for this — a sequence of typed expressions and results. Add a "Share" action that
turns the current tape into a small, thermal-receipt-styled image (monospace type, dotted rule,
subtotal/total framing, a tiny NumPad wordmark) and hands it to the system share sheet. It reframes
"I did some math on my phone" into something worth sending.

**Wow moment:** you finish splitting a bill on the numpad, tap Share, and text your friend a
tiny printed-looking receipt of the math instead of an ugly screenshot of your calculator.

**Effort:** M/L. The keyboard extension can't present `UIActivityViewController` itself, so this
follows the project's *existing* deep-link handoff pattern (`numpad://store-preview?source=...`):
Result Tape's Share button writes the tape data to the app group and opens
`numpad://receipt`; the container app reads it, renders one static receipt template, and presents
the real share sheet. No new frameworks — just the render-to-image view and the round-trip through
the app group, both patterns the codebase already has instances of.

**Risk:** Low–medium. Mostly UI work. The one fiddly part is making the extension→app handoff feel
instant rather than jarring (a visible "opening NumPad…" transition, same UX problem the store deep
link already solved). No network, no privacy concern — the data never leaves the device except via
the user's own explicit share action.

**Wow-per-effort: 8/10**

**First shippable slice:** Result Tape only (it's already GA), one fixed receipt template, Messages/
Files/AirDrop via the stock share sheet — no calculator-overlay integration, no template picker, no
customization yet.

## 4. Sass Mode — an opt-in personality dial for the overlays

**Pitch:** CARROT Weather's biggest lesson is that personality, expressed through copy the user
already has to read anyway, is a cheap and durable design differentiator — it doesn't decay the way
a one-off animation gimmick does, because it's driven by *the user's own numbers* every time,
so it never repeats the same way twice. NumPad's TAX/TIP overlay already computes a tip percentage
every single use — that's a perfect, low-risk surface to swap a flat "Tip: 18%" label for a reactive
line that changes tone based on the number: stingy tips get gently roasted, generous ones get
praised, round numbers get commented on. Ship it as an explicit opt-in toggle (not a personality
*replacing* the neutral default) so it's additive, never a UX regression for anyone who wants it
straightforward.

**Wow moment:** you tip 10% on a $200 dinner and the tax overlay quietly calls you out for it, in a
tone you chose to turn on.

**Effort:** S/M. A `UserPrefs`-style boolean toggle (`sassModeEnabled`, same pattern as
`hapticsEnabled`) plus a small array of hardcoded reaction strings swapped into
`TaxTipView`'s existing summary label based on the already-computed tip percentage — zero new views,
zero new computation (`TaxTipMath` already produces the number being reacted to).

**Risk:** Low technically, but real on tone and locale: shipping snark well is a taste problem, not
an engineering one, so start narrow and English-only rather than pushing it through the project's
49-locale pass immediately (per the existing pattern of shipping English first and flagging
"needs native review" for translation, seen in the last two localization commits). Keep it strictly
opt-in so it never becomes the thing a reviewer 1-stars the app over.

**Wow-per-effort: 7/10**

**First shippable slice:** TaxTipView only, English only, one Settings toggle, 6–8 hardcoded reaction
lines bucketed by tip-percentage range. Expand to Result Tape / Conversion overlay copy and other
locales only after this one surface proves out.

## 5. Keyboard Cards — export & share a Custom Keyboard

**Pitch:** The Custom Keyboard editor (shipped `618de734`, with drag reorder and a key-library
palette) is Pro's headline feature and, per its own design doc, the thing worth building an entire
single-page editor around — but right now a hand-built layout is invisible to anyone but its owner.
Let a user export their `CustomKeyboardConfig` as a small file and AirDrop/Message it to a friend,
who opens it and it drops straight into *their* editor as a starting layout. This turns "I spent 10
minutes building the perfect numpad" from a private satisfaction into a social one — the same way
sharing a VS Code theme or a Notion template works.

**Wow moment:** you AirDrop your custom keyboard to a friend at lunch and it just... shows up in
their editor, fully built, columns and all.

**Effort:** M/L. `CustomKeyboardConfig` is already a clean, shared (app + Keyboard target) Codable
model, so encoding it as JSON is nearly free. The right v1 mechanism is a plain `.numpadkbd` file +
`UIDocumentPickerViewController`/the system share sheet (AirDrop, Messages, Files) — deliberately
**not** a hosted link with a backend, since that would need server infra and violate the
no-network-without-Full-Access posture the rest of the app holds to. Import is a second slice: a
`numpad://import-keyboard` handler (same URL-scheme pattern already used for store deep links) that
decodes the file, runs it through the same input-validation NumPad already needs everywhere
(size caps, sanitize slot text, reject malformed/future-versioned configs), and asks
"Replace your current custom keyboard?" before writing to `CustomKeyboardStore`.

**Risk:** Medium. The interesting risk isn't the encode/decode, it's format stability —
`CustomKeyboardConfig` will keep evolving (it already has), so the export format needs an explicit
version field from day one, or a future config change silently breaks old shared files. Also a
genuine security-boundary case: an imported file is untrusted input and must be validated exactly
like any other external data before it's written to `CustomKeyboardStore`, not trusted blindly.

**Wow-per-effort: 7/10**

**First shippable slice:** export only — an "Export Keyboard" action in the editor that serializes
the current `CustomKeyboardConfig` (with a version tag) to a `.numpadkbd` file and opens the stock
share sheet. Import (the receiving side, and the "replace?" confirmation flow) ships as the very
next slice once export round-trips cleanly.

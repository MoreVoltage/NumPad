## 1. DONE (verified in code)

- **Version bump to 2.0 (build 10), both targets.** `IPHONEOS_DEPLOYMENT_TARGET = 16.0` and
  `MARKETING_VERSION = 2.0` / `CURRENT_PROJECT_VERSION = 10` are identical across all 10 build
  configs in `NumPad.xcodeproj/project.pbxproj`; both `Info.plist`s reference the same
  `$(MARKETING_VERSION)` / `$(CURRENT_PROJECT_VERSION)` build variables — no drift possible.
  (Bumped in `3f021fcc`.)
- **6-pack à la carte catalog matches code.** `ProductCatalog` (`SharedExtensions.swift:270-283`)
  and RC's `packs_enabled` default (`"math,math2,finance,symbols,programmer,datetime,units,cooking"`,
  `SharedExtensions.swift:1431`) agree: base (default/math/math2) + 6 sellable packs
  (finance/symbols/programmer/datetime/units/cooking) + `numpad.pro.lifetime` +
  `numpad.pro.lifetime.earlybird` = 8 product IDs total.
- **ASC IAP staging tooling exists and targets the right 4 missing products.**
  `marketing/asc/iap_create.py` (draft creation) and `marketing/asc/iap_metadata.py`
  (localization/price/screenshot) both correctly enumerate the same four still-missing
  non-consumables: `numpad.pro.lifetime.earlybird`, `numpad.pack.datetime`, `numpad.pack.units`,
  `numpad.pack.cooking`. Both are dry-run-by-default, `--apply`-gated, never submit. (Committed
  `1cfa308c`, currently untracked-turned-committed this session.)
- **Notification-reply keyboard-height regression fix is real and unit-tested.**
  `KeyboardViewController.defaultKeyboardHeight()` (`Keyboard/KeyboardViewController.swift:~270`)
  now calls a pure `KeyboardHeightPreset.clampCeilingContainerHeight(windowHeight:screenHeight:)`
  (`NumPad/Libraries/Keyboard.swift`, new) instead of trusting
  `inputView?.superview?.bounds.height` when `view.window` is nil — the exact bug (host's
  placeholder input view reports a tiny height before window attachment, starving the 50%
  container cap below `minHeight` and pinning every preset to 220pt). 90 lines of new unit tests
  in `NumPadTests/NumPadTests.swift`. (Commit `90d40f82`.) Logic is proven; **real-host behavior
  still needs the device pass below.**
- **zh-HK cleanup landed.** `NumPad/zh-HK.lproj/` no longer has a `Localizable.strings` (only
  storyboard placeholder `.strings` remain) — it now falls back to `zh-Hant` as intended.
  (Commit `9fb0d3e2`.)
- **New custom-keyboard-editor strings are machine-translated in all 15 non-English `NumPad`
  locales**, not just English fallback — spot-checked `de.lproj/Localizable.strings:139-250`
  against `en.lproj` and confirmed real German text ("Reihe 1", "Linkshänder", etc.), not the
  English literal. This *supersedes* the deferred-log's "all other locales fall back to English"
  note — that's now stale; translation happened, native review has not (see owner-gated list).
  (Commits `ebaddc4c`, `c561edc3`, `dae8043e`, `34b7a308`, plus one more localize-only commit for
  2.0-finalization strings not yet identified by hash in this pass.)
- **No uncommitted files, no stray TODO/FIXME/XXX added since master.** `git status --porcelain`
  is clean (the three files flagged untracked at session start —
  `docs/plans/2026-07-03-secondary-keypress-design.md`, `marketing/asc/iap_create.py`,
  `marketing/asc/iap_metadata.py` — are all now committed, in `69f6f0d2` and `1cfa308c`).
  Diffed `master...HEAD` line-by-line for added `TODO`/`FIXME`/`XXX`: the only hit is a literal
  `AuthKey_XXXXXXXXXX.p8` filename placeholder in `iap_create.py`'s usage comment — not a marker.
- **DEBUG surface is correctly fenced — verified two routes explicitly, per the task's ask:**
  - **Deep-link routes:** `NumPad/Libraries/DebugDeepLinkRoute.swift` is wrapped in a single
    top-to-bottom `#if DEBUG ... #endif` (whole file, lines 12/100) — zero symbols exist outside
    DEBUG. `ViewController.swift` guards every call site (`shouldSkipOnboarding` at L129-133,
    deep-link dispatch at L326-330, handler + launch-arg replay at L333-365) with matching
    `#if DEBUG`/`#endif` pairs.
  - **Store "Debug" section:** only appended to `visibleSections` inside `#if DEBUG`
    (`StoreViewController.swift:24-26`); its cell body is `#if DEBUG ... #else return
    UITableViewCell() #endif` (L486-521) so a Release build can't even construct the row content
    if the section were somehow reachable. The separate "Feature Flags (Beta)" section uses
    `FeatureFlags.experimentalUIVisible`, which is `#if DEBUG → true` / else
    `Bundle.main.appStoreReceiptURL?.lastPathComponent == "sandboxReceipt"` (`SharedExtensions.swift:662-668`)
    — the standard TestFlight-sandbox-receipt check, not reachable on a production App Store
    receipt. Both are correctly gated for release.

- **iCloud KVS entitlement declared** — `com.apple.developer.ubiquity-kvstore-identifier` present

## 2. SHIP-BLOCKERS (must fix before submission — none require ASC/device access)

1. **49-locale App Store metadata still describes 1.8.1; 2.0 rewrite hasn't started for any
   locale but en-US.** `git log --oneline -- fastlane/metadata` shows the last touch was
   `50d8e2cd` ("2.0 en-US metadata rewrite") — every other locale folder (50 total under
   `fastlane/metadata/`, confirming the "49 other locales" figure) is untouched since `0c8441be`
   (the 1.8.1 bump). Spot-checked `de-DE`, `fr-FR`, `ja`, `zh-Hans` `description.txt`: all still
   read the pre-2.0 pitch (no custom keyboard, no 6-pack catalog, no Pro/à la carte framing).
   There is no `release_notes_2_0.py`-equivalent pipeline yet (only `release_notes_1_8_0.py`
   exists, and per its own docstring it only hand-writes localized copy for "top revenue markets,"
   English elsewhere — so even a from-scratch run wouldn't reach all 49). This is content work,
   not an ASC-console action — doable pre-submission, not owner-gated.
2. **Store screenshots are stale — predate the entire 2.0 UX overhaul.** Every file under
   `fastlane/screenshots/en-US/` (and the iPad set) is dated **Jun 18**; the 6-pack catalog wasn't
   finalized until `51d2e8a8`+ (Jun 24) and the custom keyboard editor/paywall refresh landed
   Jul 3 (`68bc3ccd`, `618de734`). The checklist's own "refresh screenshots if they show the old
   pack set / store" condition is true — they need regenerating (and each of the 4 new/renamed
   IAP products also needs one review screenshot each per `iap_metadata.py`, which currently
   just reuses an existing en-US app screenshot as a placeholder — fine for IAP review, not a
   substitute for the App Store product-page screenshots).

Neither blocks the *binary* from building or passing tests — both are marketing-asset gaps that
would otherwise surface only during App Review or embarrass the listing post-launch.

### Minor / non-blocking nits worth a look
- `marketing/asc/iap_create.py`'s own docstring says "Create the **two** missing... IAPs" (line 4)
  but the script (and its own `Creates:` list two lines down) actually targets **four**:
  `earlybird`, `datetime`, `units`, `cooking`. Harmless (the code is right, the header comment
  lied to itself), but worth a one-line fix so whoever runs it isn't confused about scope.
- `2026-06-24-2.0-ship-checklist.md` §1 and the deferred-log's "ASC catalog is now 6 IAPs" note are
  now **both** stale relative to `iap_create.py`/code: the checklist still lists
  `.scientific`/`.business`/`.intl`/`.programmerplus` (decode-only ghost packs, never sellable) and
  omits `.cooking` entirely (added after that note was written). Anyone following the checklist
  literally would create the wrong four products. The scripts are the current source of truth —
  recommend a doc pass syncing the checklist to match before using it as the ASC runbook.
- `NumPad/Products.storekit` isn't wired into any shared `.xcscheme`'s StoreKit Configuration —
  simulator purchase testing per checklist §4 requires a manual one-time Edit Scheme step first.
- Full test suite (**290** `NumPadTests` methods across 13 files + **11** `NumPadUITests` methods
  across 2 files, current count) was not re-executed end-to-end in this pass (no build/xcodebuild
  run — kept this audit read-only and avoided simulator contention). The ship-checklist's cited
  "117 tests" is stale documentation, not a red flag — the suite grew substantially since; but the
  claim of "all green" hasn't been independently re-verified here and should be before archiving.

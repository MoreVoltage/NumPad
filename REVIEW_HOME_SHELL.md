## Verified OK (no change needed)

- **iPhone root is the classic Home.** `ViewController.installContentShell()` embeds `HomeViewController` plus the demo field when the idiom is `.phone`, and the iPad Studio workspace otherwise. `StudioTabBarController` is only built by `StudioNavigationFactory.makePhoneShell()`, and only tests call that. SceneDelegate keeps the storyboard root. New tests: `test_iPhoneProductionRootIsClassicHomeNotStudioTabBar` (real storyboard VC, no idiom override, walks the child hierarchy for any `UITabBarController` or Studio workspace) and `test_noProductionCodeInstallsStudioPhoneShell`.
- **No subscriptions.** `ProductCatalog.allProductIDs` contains exactly 2 lifetime Pro IDs and 6 packs. `Products.storekit` has 8 `NonConsumable` products and empty `subscriptionGroups` / `nonRenewingSubscriptions`. The branch *removed* live's dormant `numpad.pro.sub.*` restore handling and `isProSubscriptionActive`. Live never sold a subscription, so no user loses an entitlement. New tests: `NoSubscriptionProductsTests` (catalog, StoreKit config, source scan).
- **Monetization vs live.** `isProEntitled` = purchased or grandfathered (live also OR'd in the never-sold subscription). Restore now reports success on `isProPurchased || isGrandfathered || packs` instead of `isProEntitled || packs`. That is equivalent outside DEBUG overrides. No price or gating-map changes beyond the subscription removal.
- **Glide stays dark.** `qwertyGlideTyping` passes through `effective()`. The only place that sets it to true (`QwertySwipeCalibrationViewController`) is compiled under `#if DEBUG && NUMPAD_PRIVATE_SWIPE`.
- **Calibration entry point.** Home → NumPad Type (flag-gated) → Calibration section, row 0 → full-screen `UINavigationController(QwertyCalibrationViewController)`. The private swipe row is DEBUG + `NUMPAD_PRIVATE_SWIPE` only. New tests: `QwertyCalibrationEntryPointTests` and `test_qwertyRowLeadsToSetupScreen`.
- **Keyboard height.** `defaultKeyboardHeight()` still uses `clampCeilingContainerHeight` (which this branch hardened against keyboard-sized windows). `isFloatingKeyboard` deliberately reads the raw window height, as documented. Not a regression.
- **Profile migration on launch.** `KeyboardProfileMigration.runIfNeeded()` only snapshots current settings into a store. It does not rewrite live settings. `ManagedProfileCoordinator` is a no-op unless an MDM managed dictionary is present.

## Recommendations (not changed — need an owner decision or carry more risk)

| # | Sev | Item |
|---|-----|------|
| R1 | **HIGH** | **The version is still 2.1.1 (16), the same marketing version as the live release.** Any submission needs a new marketing version (for example 2.1.2) or App Store Connect will reject it. Not bumped, per instructions. |
| R2 | **MEDIUM** | **What's New was removed** (`WhatsNewViewController`, `WhatsNew`, `WhatsNewNotification`, `WhatsNewChipView`, the `numpad://whats-new` route, and the `UNUserNotificationCenter` delegate). This is a live feature. A What's New local notification already scheduled by 2.1.1 on a user's device will now open the app with no sheet (harmless, but a dead tap). Decide whether to restore it or ship without it on purpose. |
| R3 | **MEDIUM** | **Saved setups (profiles) is new on the phone.** It pushes `SavedSetupsStudioViewController`, which is Studio UI, and adds an exported `.numpadprofile` UTI plus document-open handling (`MoveSetupsViewController`). None of this exists in live 2.1.1. If the release goal is "classic Home, no Studio on iPhone", hide `.profiles` on phone and drop the document types from Info.plist. If the goal is to ship profiles, it needs a device QA pass, including importing a crafted profile file. |
| R4 | **MEDIUM** | **The F1 fix depends on `experimentalUIVisible` working correctly in the keyboard extension** (`appStoreReceiptURL.lastPathComponent == "sandboxReceipt"`). Glide's dark posture already relies on the same mechanism. Confirm on a TestFlight build that the ABC key still appears for Pro testers, and on a production-signed build that it does not. |
| R5 | **MEDIUM** | **Remote Config default `full_keyboard_enabled: true`** (`SharedExtensions.swift:1900`). With F1 this no longer exposes QWERTY in App Store builds. At GA, flip the console value deliberately rather than relying on the in-app default. |
| R6 | LOW | **Home → NumPad Pro price fallback** changed from "$11.99" to "Unlock more choices" when StoreKit has not loaded. This is a copy decision. |
| R7 | LOW | **Dead or test-only Studio code** ships in the phone binary: `StudioNavigationFactory.makePhoneShell`, `StudioTabBarController`, and the Studio tab VCs (only tests use them on phone). Consider moving them behind `#if DEBUG` or deleting them once iPad Studio settles. The `ViewController.studioTabs` property is always nil. |
| R8 | LOW | `HomeViewController.didSelectRowAt` still has a `case .dashboard: break`. It is unreachable on phone after F3, but if `.dashboard` returns to the phone model it will be a dead tap again. Consider routing it to `DashboardViewController` instead. |
| R9 | LOW | The NumPad Type row's detail text shows the NumPad keyboard's enabled state (`KeyboardStatusPresentation`), not whether the QWERTY page is available. Pro-locked users see "Enabled" but no ABC key. |
| R10 | INFO | XCUITest suites (`NumPadUITests`, including the QWERTY smoke tests) were **not** run in this pass. Only the `NumPadTests` unit suite ran. |
